## 1️⃣ What Is a Static Website? 🌐

> 💡 **Core Idea:** A static website is made of **plain files that run in the browser**: **HTML, CSS, and JavaScript**. There's **no server-side component**: no Java web app, no Python app, no REST API behind it.

### 🧒 In Simple Words: Brochure vs Restaurant 📰🍽️

| | 📰 **Static Website** | 🍽️ **Dynamic Website** |
|---|---|---|
| 🧒 **Picture** | A **printed brochure**. Everyone gets the **same pages**, handed over as they are | A **restaurant kitchen**. A chef **prepares something fresh** for each order |
| ⚙️ **Needs a server program?** | ❌ No, just files to hand out | ✅ Yes, code runs on the server |
| 🗄️ **Where to host** | ✅ **S3 works great** | EC2, Elastic Beanstalk, containers, etc. |

> 🎯 **Key Insight:** S3 is perfect for static sites: it's **cheap, highly durable and scalable**, and there's **no server to manage**.

---

## 2️⃣ Step 1: Enable Static Website Hosting ⚙️

```
Bucket → Properties → Static website hosting → Edit → Enable
   ✅ "Use this bucket to host a website"
   📄 Index document: index.html
   → Save
```

> 💡 The **index document** is the **default page**, the one S3 shows when someone visits your site's address.

### ❓ Is That Enough?

```
❌ NO! Enabling hosting alone does NOT make the site work.
   We still need: (1) the website files, and (2) public permissions.
```

---

## 3️⃣ Step 2: Upload the Website Files ⬆️

```
Bucket → Objects → Upload → select the site's files and folders
   (in the demo: cloud, index.html, process, tools) → Upload
```

> 🎯 Make sure `index.html` is at the **root** of the bucket, matching the index document name you entered.

### 🧪 Quick Test

> If you click `index.html` and open its URL now, you'll get:
>
> ```
> ❌ Access Denied
> ```
>
> That's **good news** in a way: S3 is **private by default**, so nothing is public until you say so. Let's fix it.

---

## 4️⃣ Step 3: Allow Public Access 🔓

> 💡 **Remember Lecture 142:** "Block all public access" is **ON by default**. We must turn it off for this bucket.

```
Bucket → Permissions → Block public access → Edit
   ⬜ Uncheck "Block all public access"
   → Save → type "confirm"
```

### 🧪 Test Again

```
❌ STILL "Access Denied"!
```

> 🤔 **Why?** Turning off the block only **removes the safety lock**. It doesn't **grant** anyone permission. We need one more step.

### 🧒 In Simple Words: Two Locks 🔐🔐

> 1. **Lock #1: Block public access.** The **master lock** on the front door. (Now removed.)
> 2. **Lock #2: Permissions.** The **guest list**. If the list says "nobody is allowed," visitors still can't enter, even with the master lock open.
>
> Both must allow access before visitors can come in.

---

## 5️⃣ Step 4: Add a Bucket Policy 📜

> 💡 **Core Idea:** A **bucket policy** is a set of rules that says **who can do what** with the bucket's objects. We need one that says **"Everyone can read the files."**

```
Bucket → Permissions → Bucket policy → Edit
```

> 📚 **Tip from the demo:** Open the **Documentation → Bucket Policy Examples** link, and pick **"Read-only permission to anonymous users."** Copy it, then **replace the example bucket name** with your own.

### 📄 The Policy

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": ["s3:GetObject"],
      "Resource": ["arn:aws:s3:::YOUR-BUCKET-NAME/*"]
    }
  ]
}
```

### 🔍 Reading the Policy in Plain English

| Line | Meaning |
|---|---|
| `"Effect": "Allow"` | This rule **allows** something |
| `"Principal": "*"` | **Everyone**, including anonymous visitors |
| `"Action": "s3:GetObject"` | They may **read (download) objects**, and nothing else |
| `"Resource": "arn:aws:s3:::YOUR-BUCKET-NAME/*"` | **All objects** in that bucket (`/*` means "everything inside") |

> 🧒 **In simple words:** It's a **notice on the warehouse door**: *"Anyone may look at (but not change) the items in this room."*

> ⚠️ **Replace `YOUR-BUCKET-NAME`** with your real bucket name (the demo used `my-bucket-in28minutes`), then **Save**.

### 🎉 Result

```
✅ Refresh the page → the website loads!
```

## 6️⃣ Troubleshooting "Access Denied" 🕵️

| ✅ Check | What to Look For |
|---|---|
| 1️⃣ | **Static website hosting** is enabled and `index.html` is set |
| 2️⃣ | Files are **uploaded** to the right place (`index.html` at the root) |
| 3️⃣ | **Block public access** is **off** for the bucket |
| 4️⃣ | The **bucket policy** allows `s3:GetObject` for everyone |
| 5️⃣ | The **bucket name in the policy** matches your real bucket exactly |

## ❓ Extra Important Question: "Can an S3-hosted website use HTTPS and my own domain name, like www.mycompany.com?"

> 💡 **Answer:** Not with S3's website feature alone. The **S3 website endpoint serves plain HTTP only** (no HTTPS). That's fine for a demo, but **real sites need HTTPS**. The standard solution is to put **Amazon CloudFront** (AWS's content delivery network, which we'll meet later) **in front of the bucket**. CloudFront adds **HTTPS**, supports **your own domain name** (with **Route 53** for DNS), and serves your site from **edge locations** close to users, making it **faster worldwide**.
>
> 📝 **Also note:** In the demo, the instructor opens each file's **Object URL**. For a real site, you'd normally share the bucket's **website endpoint** (shown at the bottom of the **Static website hosting** section), which serves your **index document automatically**.
>
> 🧒 **In simple words:** S3 is the **warehouse** holding your brochure. CloudFront is a **fancy shopfront** with a **secure door (HTTPS)**, **your brand name on the sign**, and **branches in many cities**.

## ✅ Final Takeaways

```
🌐 Static website = HTML + CSS + JavaScript only (no server-side code)
🗄️ S3 is a great, cheap, scalable home for static sites
⚙️ Hosting needs FOUR things: enable hosting + upload files + unblock public access + bucket policy
🔐 Block public access is a master lock; the bucket policy is the guest list. You need BOTH open
📜 Policy: Allow + Principal "*" + s3:GetObject + arn:aws:s3:::bucket/*
❌ "Access Denied" = a permission is still missing, so work through the checklist
🔒 S3 website endpoints are HTTP only → use CloudFront for HTTPS and a custom domain
⚠️ Only make PUBLIC what's meant to be public
```
