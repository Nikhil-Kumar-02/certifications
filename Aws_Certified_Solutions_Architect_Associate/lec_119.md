## 1️⃣ Create the Custom VPC 🌐

Navigate: **VPC → Your VPCs → Create VPC**

| Setting | Value |
|---|---|
| 📛 **Name** | `my-custom-vpc` |
| 🔢 **IPv4 CIDR block** | `69.208.0.0/16` |
| 🌐 **IPv6 CIDR** | None (not needed) |
| 🏢 **Tenancy** | Default |

### 🧪 Mini Experiment: Try `/15`

```
❌ 69.208.0.0/15 → ERROR: "Block sizes must be between /16 and /28"
✅ 69.208.0.0/16 → Works (the widest range a VPC allows)
```

> 🎯 This confirms what we learned in Lecture 118: VPC sizes can only be between `/16` and `/28`.

### 🧒 What Is "Tenancy"? (In Simple Words)

| Tenancy | Meaning | Simple Analogy |
|---|---|---|
| **Default** | Your servers may share the same physical machine with other AWS customers (kept safely isolated) | 🏢 Living in an **apartment building**: shared building, private flat |
| **Dedicated** | Your servers run on hardware used **only by you** | 🏠 Living in your **own independent house** |

> 💡 Dedicated costs more. Enterprises with strict compliance rules choose it. If your VPC is dedicated, the EC2 instances inside it are dedicated too. We use **Default** for this demo.

---

## 2️⃣ Create the Private Subnet 🔒

Navigate: **VPC → Subnets → Create subnet**

| Setting | Value |
|---|---|
| 📛 **Name** | `my-private-subnet` |
| 🌐 **VPC** | `my-custom-vpc` |
| 🏢 **Availability Zone** | The first one in your region (e.g., `ap-south-1a`) |
| 🔢 **IPv4 CIDR** | `69.208.0.0/24` |

> 🧒 **Why `/24`?** The last 8 bits can change, so 2⁸ = **256 addresses**. That's a nice small slice of our big `/16` VPC.

> 💡 **Remember:** The subnet CIDR must fit **inside** the VPC CIDR. If the VPC were only `/24`, the subnet could be `/24` or smaller.

---

## 3️⃣ Create the Public Subnet 🌍

| Setting | Value |
|---|---|
| 📛 **Name** | `my-public-subnet` |
| 🌐 **VPC** | `my-custom-vpc` |
| 🏢 **Availability Zone** | A **different** AZ from the private one (e.g., `ap-south-1b`) |
| 🔢 **IPv4 CIDR** | `69.208.1.0/24` |

> 🧒 **Note the pattern:** Private subnet = `69.208.0` ... and Public subnet = `69.208.1` ... They don't overlap. This is how you can tell the two apart just by looking at an IP address.

> ⚠️ **Name vs reality:** Right now, calling it "public" is just a **label we typed**. It doesn't make the subnet public yet. We'll see why in the next lecture!

### ✅ Where We Are Now

```
🌐 my-custom-vpc (69.208.0.0/16)
   ├── 🔒 my-private-subnet (69.208.0.0/24) → AZ 1a
   └── 🌍 my-public-subnet  (69.208.1.0/24) → AZ 1b
```

---

## 4️⃣ Launch the Private EC2 Instance 🖥️🔒

Open **EC2 in a separate browser tab** (one tab for VPC, one for EC2). Then click **Launch Instance**.

| Setting | Value |
|---|---|
| 💿 **AMI** | Amazon Linux 2 |
| 💻 **Instance type** | `t2.micro` (free tier eligible) |
| 🌐 **Network (VPC)** | `my-custom-vpc` (NOT the default!) |
| 🧩 **Subnet** | `my-private-subnet` |
| 🌍 **Auto-assign Public IP** | **Enable** (the subnet default is "disabled", so we change it) |
| 💾 **Storage** | Default |
| 🏷️ **Tag** | Name = `Private-EC2-Instance` |
| 🔐 **Security Group** | **Create new**: `ec2-security-group`, allow **SSH** |
| 🔑 **Key pair** | Existing one (e.g., `ec2-default`), or create a new one |

### 🧒 Why a New Security Group? (In Simple Words)

> 🔐 Security groups are **tied to one VPC**. The ones you made earlier belong to the default VPC and won't show up in `my-custom-vpc`. It's like a staff ID card that only works in one building. So you create a fresh one for the new VPC.

## 5️⃣ Launch the Public EC2 Instance 🖥️🌍

Same steps as above, with these differences:

| Setting | Value |
|---|---|
| 🧩 **Subnet** | `my-public-subnet` |
| 🌍 **Auto-assign Public IP** | **Enable** |
| 🏷️ **Tag** | Name = `Public-EC2-Instance` |
| 🔐 **Security Group** | **Select existing**: `ec2-security-group` (the one we just created) |

## ❓ Extra Important Question: "Why are we giving a public IP to the instance in the PRIVATE subnet? Isn't that defeating the purpose?"

> 💡 **Answer:** Good catch! In a properly designed setup, a truly private instance would **not** have a public IP. We're doing it here **on purpose, for learning**. Giving both instances a public IP lets us run the same tests on both and compare. It sets up the key lesson in the next lecture: **a public IP alone doesn't make an instance reachable**. What really makes a subnet "public" is its **route to the internet**, not its name or whether its instances have public IPs. Hold on to that thought, it's one of the most tested ideas in the VPC section.

## ✅ Final Takeaways

```
🌐 Creating a VPC = give it a name + a CIDR block (/16 to /28)
🧩 Creating a subnet = pick the VPC + an Availability Zone + a smaller CIDR inside the VPC
🏢 Default tenancy = shared hardware | Dedicated tenancy = hardware just for you
🔐 Security groups belong to ONE VPC, so make a new one for a new VPC
🏷️ Naming a subnet "public" does NOT make it public (the next lecture explains why!)
```
