## 🎯 What This Lecture Is About

> 🎬 Remember how our instances couldn't be reached, even with public IPs and open security groups? Now we fix it by building the missing path to the internet, step by step.

```
1️⃣ Create an Internet Gateway
2️⃣ Attach It to Our VPC
3️⃣ Test (It Still Fails!)
4️⃣ Understand the Route Tables
5️⃣ Add the Route to the Internet
6️⃣ Test Again (Success!)
7️⃣ The New Problem
```

---

## 🧒 The 3-Step Recipe in Simple Words

> 🏘️ Think of our VPC as a gated colony. To open it to the outside world, you need **three things**:
>
> 1. 🚪 **Build a main gate** (create the Internet Gateway)
> 2. 🔗 **Fix the gate onto your colony** (attach it to the VPC)
> 3. 🪧 **Put up a signboard pointing to the gate** (add a route in the route table)
>
> Skip any one of these and nobody gets in or out.

---

## 1️⃣ Create an Internet Gateway 🚪

Navigate: **VPC → Internet Gateways → Create internet gateway**

```
📛 Name: my-internet-gateway
```

### 👀 What You'll See First

| Internet Gateway | Status |
|---|---|
| 🏠 **Default one** | Already **attached** to the default VPC (AWS created this for you) |
| 🆕 **`my-internet-gateway`** | **Detached**, not connected to any VPC yet |

> 📌 **Exam Alert:** An Internet Gateway has a **one-to-one relationship** with a VPC. One gateway can serve **only one VPC**, and one VPC uses **only one** internet gateway. You can't share one gateway across several VPCs.

> ⚠️ **Console Tip:** The default gateway may be pre-selected in the list. Make sure you **select your new one** before the next step.

---

## 2️⃣ Attach It to Our VPC 🔗

```
1️⃣ Select my-internet-gateway
2️⃣ Actions → Attach to VPC
3️⃣ Choose my-custom-vpc
4️⃣ Click Attach
```

> 🧒 **In simple words:** A newly created gateway is like a gate lying in a warehouse. It isn't fixed to any colony yet. "Attach" is the step where you actually install it on your colony's wall.

---

## 3️⃣ Test: Does Ping Work Now? 🏓

```
❌ Result: Still NOT working!
```

> 🤔 We built the gate and attached it, yet it still fails. Why? Because **nobody has told the traffic to use the gate.** We need the signboard.

---

## 4️⃣ Understand the Route Tables 📋

Navigate: **VPC → Route Tables**. You'll see **two** route tables:

| Route Table | Where It Came From |
|---|---|
| 🏠 **Default VPC's route table** | Created by AWS along with the default VPC (every region has one) |
| 🆕 **Our custom VPC's route table** | **Created automatically** whenever we created `my-custom-vpc` |

> 💡 **Core Idea:** Every VPC automatically gets its own route table.

### 🏷️ Tip: Rename Them!

To tell them apart, look at the **VPC ID** column, then give them clear names:

```
My VPC Route Table      → the one linked to my-custom-vpc
Default VPC Route Table → the one linked to the default VPC
```

### 🔍 Compare Their Routes

| Route Table | Routes Inside | What It Means |
|---|---|---|
| 🏠 **Default VPC Route Table** | 1. Local route (VPC's CIDR → local) <br> 2. `0.0.0.0/0` → Internet Gateway | Can talk internally **and** reach the internet ✅ |
| 🆕 **My VPC Route Table** | Only: `69.208.0.0/16` → local | Can talk internally only. **No route to the internet** ❌ |

> 🎯 **Key Insight:** Our custom VPC's route table had **no route to the internet gateway**. That's why traffic couldn't go in or out, even with the gateway attached.

---

## 5️⃣ Add the Route to the Internet 🪧

```
1️⃣ Select My VPC Route Table
2️⃣ Go to the Routes tab → Edit routes → Add route
3️⃣ Destination: 0.0.0.0/0     (all addresses)
4️⃣ Target: Internet Gateway → my-internet-gateway
5️⃣ Save routes
```

> 🧒 **In simple words:** We put up the signboard: "**Anything not inside our colony? Take the main gate.**"

> 💡 **Console Tip:** When you type `0.0.0.0/0`, make sure you **click the suggestion** that appears, so the route is picked correctly.

---

## 6️⃣ Test Again 🎉

| Test | Before | After |
|---|---|---|
| 🏓 **Ping the public IP** | ❌ Timed out | ✅ **Works!** |
| 💻 **EC2 Instance Connect** to `Public-EC2-Instance` | ❌ Failed | ✅ **Connected** |
| 💻 **EC2 Instance Connect** to `Private-EC2-Instance` | ❌ Failed | ✅ **Connected** |
| 🌐 **`curl google.com`** from the *Private* instance | ❌ No access | ✅ Got a response |

> 🧪 **Quick check:** Running `whoami` inside the connected instance returns `ec2-user`, which confirms we're logged in to the instance.

---

## 7️⃣ The New Problem 😬

> ⚠️ **Wait, something's wrong.** Our *private* instance can now be reached from the internet, and it can reach the internet too.

```
BEFORE: Both subnets were effectively PRIVATE
NOW:    Both subnets are effectively PUBLIC   ← we wanted only ONE public!
```

### 🤔 Why Did This Happen? (In Simple Words)

> The route table we edited belongs to the **whole VPC**, and by default **every subnet uses it**. So when we added the "take the main gate" signboard, it applied to **both streets** in the colony, not just the public one.
>
> The instructor calls this a **"hack"**: it got us connected quickly so we could see things work, but it isn't the right final design.

> 🎯 **The Goal:** Make the **public subnet** public and keep the **private subnet** truly private. We'll fix this in the next lecture.

---

## ❓ Extra Important Question: "Why does the private subnet get internet access just because I edited 'My VPC Route Table'? I never touched the private subnet!"

> 💡 **Answer:** Because a subnet that isn't linked to a specific route table **automatically uses the VPC's main route table**. We never linked either subnet to anything special, so both fell back on the same table, the one we just edited. The usual fix is a two-table design:
>
> - 🔒 **Main route table:** keep it **without** an internet route. Subnets use it by default, so anything you forget to configure stays private (safe by default).
> - 🌍 **A separate "public" route table:** add the `0.0.0.0/0 → Internet Gateway` route here, and **link only the public subnet** to it.
>
> That way, being public is something you choose on purpose, not something that happens by accident.

## ✅ Final Takeaways

```
🚪 Create an Internet Gateway → 🔗 Attach it to the VPC → 🪧 Add a 0.0.0.0/0 route to it
🔗 One Internet Gateway ↔ ONE VPC (a one-to-one relationship)
📋 Every VPC automatically gets its own route table
🚫 Gateway attached but no route = still NO internet access
⚠️ Editing the VPC's shared route table makes EVERY subnet using it public
🎯 Next challenge: keep the private subnet truly private
```
