## 1️⃣ Why Do We Need CIDR? 🤔

> 💡 **Core Idea:** Resources in the same network typically use similar addresses, which makes routing between them easy. But how do you **specify a range** of addresses without listing every single one?

```
❌ Listing all addresses one by one: 69.208.0.0, 69.208.0.1, 69.208.0.2 ... (tedious!)
✅ CIDR notation: 69.208.0.0/28 (represents all 16 addresses in one compact expression)
```

---

## 2️⃣ How CIDR Notation Works 🔢

```
📝 Format: <Starting IP Address>/<Number of Fixed Bits>
```

### 🎯 Example: `69.208.0.0/28`

```
📏 Total bits in an IPv4 address: 32
🔒 Fixed bits: 28
🔓 Variable bits: 32 - 28 = 4
📊 Number of addresses: 2^4 = 16
```

> 🎯 **Key Insight:** The `/28` tells you how many bits are **fixed** (identical for every address in the range). The remaining bits are **variable**, and 2 raised to the power of the variable bits tells you the total address count.

### 📐 The Core Formula

```
Number of Addresses = 2^(32 - CIDR number)
```

## 3️⃣ Using CIDR.xyz to Visualize Ranges 🛠️

> 💡 **Recommended Tool:** [CIDR.xyz](https://cidr.xyz) — a fantastic interactive tool for visualizing CIDR ranges. (Search "CIDR calculator" if that specific tool isn't available.)

### 🎓 Examples Explored

| CIDR | Fixed Bits | Variable Bits | Address Range | Total Addresses |
|---|---|---|---|---|
| `0.0.0.0/0` | 0 | 32 | Everything | ~4.3 billion |
| `0.0.0.0/16` | 16 | 16 | 0.0.0.1 → 0.0.255.254 | ~65,000 |
| `69.208.0.0/28` | 28 | 4 | 69.208.0.0 → 69.208.0.15 | 16 |

> ⚠️ **Important Detail:** Within a CIDR block, the **first and last** addresses are typically **reserved** (commonly for the router) — so usable addresses are often shown as a slightly smaller range (e.g., `.1` through `.14` instead of `.0` through `.15`).

## 4️⃣ Practice Exercises 🧠

### ❓ How many addresses does `69.208.0.0/26` represent?

```
32 - 26 = 6 variable bits
2^6 = 64 addresses
📍 Range: 69.208.0.0 → 69.208.0.63
```

### ❓ How many addresses does `69.208.0.0/30` represent?

```
32 - 30 = 2 variable bits
2^2 = 4 addresses
📍 Range: 69.208.0.0 → 69.208.0.3
```

## 5️⃣ The Critical `/0` vs `/32` Distinction ⚠️

> 📌 **This is a MUST-KNOW for the exam!**

| CIDR | Meaning |
|---|---|
| 🌐 **`0.0.0.0/0`** | **0 bits fixed** → ALL bits are variable → represents **ALL possible IP addresses** |
| 🎯 **`0.0.0.0/32`** | **32 bits fixed** → NO bits are variable → represents **exactly ONE** IP address (`0.0.0.0`) |

> 🎯 **Key Insight:** These two are **opposite extremes** on the CIDR spectrum — `/0` means "everything," `/32` means "just this one specific address."

---

## ❓ Extra Important Question: "Why does AWS reserve the first and last address of every CIDR block, and are there any OTHER reserved addresses I should know about?"

> 💡 **Answer:** The first address of a CIDR block identifies the **network address** itself (a technical placeholder, not assignable to a device), and the last address is typically the **broadcast address** (used to send data to all devices in the range) — that's standard networking behavior, not AWS-specific. But AWS actually reserves **5 addresses** in every VPC subnet, not just 2: the network address (first), the VPC router (second), the DNS server address (third), a address reserved for future use (fourth), and the broadcast address (last) — even though AWS doesn't support broadcast in a VPC, it still reserves that address for consistency with standard networking. This is worth remembering specifically for VPC subnet sizing: when planning subnet capacity, always subtract 5 addresses from your CIDR's total to know how many are actually usable for your resources.

```
📐 FORMULA: Number of Addresses = 2^(32 - CIDR number)

/0  → ALL IP addresses (~4.3 billion)
```
