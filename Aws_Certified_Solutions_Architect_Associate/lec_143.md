## 1️⃣ S3 Is Global, but Buckets Are Regional 🌍

| Level | Scope |
|---|---|
| 🌐 **Amazon S3 (the service)** | **Global**: not tied to one region |
| 🪣 **A bucket** | Created in **one specific region** (we chose `us-east-1`) |

> 💡 **A handy side effect:** Most AWS services only show you resources from the **region you're in**. S3 shows **all your buckets from all regions together** in one list, with each bucket's region shown next to it.

---

## 2️⃣ Bucket Names 📛

```
🌍 Globally unique across ALL AWS accounts
🔤 Part of the object's URL → only URL-safe characters
✅ Allowed: lowercase letters, numbers, hyphens (-), periods (.)
❌ Not allowed: spaces, uppercase letters, and other URL-unfriendly characters
```

---

## 3️⃣ Objects = Key + Value 🔑📦

> 💡 **Core Idea:** Every object in S3 is a **key-value pair**.

```
🔑 KEY   = the object's unique name (including the "path")
📦 VALUE = the content of the object (e.g., the image itself)
```

### 🎓 Examples from Our Demo

| Key | Value |
|---|---|
| `2030/course0.png` | The image `course0.png` |
| `2030/10/course1.png` | The image `course1.png` |

### 🧒 In Simple Words

> Like a **hashmap**, each key must be **unique** within a bucket. You can't have two objects with the same key. If you upload a new file with an existing key, it **replaces** the old one (unless versioning is on, which we'll see next).

### 📍 The Path to an Object

```
s3://<bucket-name>/<key>

Example: s3://my-bucket-in28minutes/2030/course0.png
```

> 💡 In the console, select an object and click **Copy path** to see this.

---

## 4️⃣ Size Limits 📏

| Limit | Value |
|---|---|
| 📦 **Number of objects per bucket** | **Unlimited** (S3 has unlimited storage) |
| 📦 **Maximum size of ONE object** | **5 TB** (that's **terabytes**, about **5,000 GB**!) |

> 📝 *Bonus fact (not in the lecture): a **single upload request** can send up to **5 GB**. For anything larger, S3 uses **multipart upload**, which splits the file into parts. The console and AWS tools do this automatically for big files.*

---

## 5️⃣ The "No Folders" Surprise 🤯

> 💡 **Core Idea:** **S3 has no hierarchy.** There are **no folders, subfolders, or sub-buckets**. There are only **keys and values**.

### 🖥️ What You See on Your Computer

```
📁 2030
   ├── 🖼️ course0.png
   ├── 📁 10
   │     ├── course1.png
   │     └── ...
   └── 📁 11
         └── ...
```

### 🗄️ What S3 Actually Stores

```
KEY                         →  VALUE
2030/course0.png            →  (image content)
2030/10/course1.png         →  (image content)
2030/10/...                 →  (image content)
2030/11/...                 →  (image content)
2030/11/...                 →  (image content)
```

> 🎯 **Result:** The folder we uploaded has **5 keys and 5 values**. That's it. No folder objects at all.

### 🧒 In Simple Words: Luggage Tags 🏷️

> Imagine a **big pile of suitcases**, each with a **luggage tag**. One tag says `2030/10/course1.png`. There are **no shelves or rooms**, just suitcases with long tags. The **slashes are simply part of the tag's text**.
>
> The S3 console is like a **helpful assistant** who reads the tags and arranges them *as if* they were in folders: "Everything starting with `2030/10/` goes in the `10` folder." It's a **display trick** (the instructor calls it "the magic of the UI"). Underneath, it's all flat.

> 🔧 **How does the console do it?** It uses S3 APIs that **list keys starting with a certain prefix** (like `2030/`), then shows them grouped as folders.

## 6️⃣ What You Can Do with an Object 🛠️

Select an object (like `course0.png`) and you'll find:

| Action | What It Does |
|---|---|
| 👁️ **Open** | View the content (opens in a **pop-up**, so disable your **pop-up blocker** if nothing happens) |
| ⬇️ **Download** | Save it to your computer |
| ✏️ **Download as** | Save it under a **different name** |
| 📋 **Copy path** | Gives you `s3://bucket/key` |

### 📋 Object Details You Can See

```
👤 Owner          → who uploaded it
🗃️ Storage class  → e.g., Standard
🔐 Encryption     → (not encrypted in our demo)
📏 Size
🔑 Key
```

> 💡 **Also:** Every object has its **own properties** and its **own permissions**, in addition to the bucket-level ones.

## ❓ Extra Important Question: "If there are no real folders, what happens when I click 'Create folder' in the console, or delete all the files in a 'folder'?"

> 💡 **Answer:** Great question, and it explains the "magic" nicely.
>
> - **Create folder:** The console creates a tiny, **empty (zero-byte) object** whose key **ends with a slash**, such as `photos/`. It's just a **placeholder** so the "folder" shows up even when it's empty.
> - **Delete all the files in a folder:** The "folder" **disappears from the view**, because no keys start with that prefix any more (unless a placeholder object like `photos/` still exists).
>
> This also means you can upload `reports/2025/jan/sales.csv` **directly** without creating any folders first. The "folders" appear automatically from the key.
>
> 🧒 **In simple words:** Creating a folder is like **putting a blank luggage tag on a hook** so the label shows up. Remove all suitcases and tags with that label, and the label vanishes.
