## 🧒 The Two Guards, One More Time

> 🏘️ **NACL** = the guard at the **street entrance** (checks everyone coming into or leaving the **subnet**)
> 💂 **Security group** = the guard at **each house's door** (checks everyone going into that **one resource**)

---

## 1️⃣ Key Differences ⚖️

| Feature | 💂 Security Group | 🚧 NACL |
|---|---|---|
| 📍 **Applies to** | A **specific resource** (EC2 instance, database) | A **subnet**, so all instances in it |
| ✅❌ **Rule types** | **Allow rules only** | **Allow AND Deny** rules |
| 🚫 **If no rule matches** | Traffic is **denied** | Traffic is **denied** |
| 🧠 **State** | **Stateful**: return traffic is **automatically allowed** | **Stateless**: you must **explicitly allow both inbound and outbound** |
| 🏆 **Rule evaluation** | **Any one matching rule** allows the traffic (they're all allow rules) | **Highest-priority rule wins** (lowest number first) |
| 🏘️ **Traffic within the same subnet** | ✅ **Applies** | ❌ **Does not apply** |

### 📌 Let's Unpack the Trickier Rows

#### 🅰️ "Applies to" (Resource vs Subnet)

> If your subnet has **1,000 instances**, the NACL rules are applied **once, at the subnet's entrance**, before traffic gets near any of them. Security groups, on the other hand, are checked **per resource**.

#### 🅱️ "Rule evaluation"

| | Security Group | NACL |
|---|---|---|
| 🧮 **How it decides** | "Is there **any** rule that allows this?" If yes → ✅ allowed | "Go down the list **from the lowest number**. The **first match** decides." |
| 🧒 **Simple picture** | A guest list: **your name appears anywhere** → you're in | A numbered checklist: the **first line that applies to you** decides, and the guard stops reading |

#### 🅲 "Traffic within the same subnet"

> 🧒 **In simple words:** If two houses are on the **same street**, visitors walking between them **never pass the street-entrance guard**. Only the **house-door guards** (security groups) check them.

```
Instance A ←→ Instance B (same subnet)
   🚧 NACL: NOT involved
   💂 Security groups: still checked
```

---

## 2️⃣ The Order Traffic Is Checked 🔀

### 🌍 Traffic Coming from OUTSIDE the Subnet

```
🌍 Traffic arrives
      ↓
🚧 NACL checks first (must allow it going IN and the reply going OUT)
      ↓  (if allowed)
💂 Security group checks next
      ↓  (if allowed)
🖥️ Reaches your resource ✅
```

> ⚠️ **If the NACL denies the traffic, it goes no further.** The security group never even gets to look at it.

### 🏠 Traffic Inside the Same Subnet

```
🖥️ Instance A → 💂 Security group check → 🖥️ Instance B ✅
(NACL is skipped)
```

## 3️⃣ Classic Scenario: "An EC2 Instance Can't Be Accessed from the Internet. What Could Be Wrong?" 🕵️

> 📌 **This is a favourite exam question.** There are several things that could go wrong. Check **all four**:

| # | ✅ Check This | What You're Looking For |
|---|---|---|
| 1️⃣ | 🌍 **Public IP or Elastic IP** | The instance **must have one**, or the internet has no address to send traffic to |
| 2️⃣ | 🚧 **NACL** | Does it allow **inbound AND outbound** traffic from **your IP**, on the **port** you're using? |
| 3️⃣ | 🪧 **Route table** | Does the subnet's route table have a **route to the Internet Gateway**? If not, it's **not a public subnet** and the instance is unreachable |
| 4️⃣ | 💂 **Security group** | Does it **allow inbound traffic from your IP** on that port? |

### 🧒 In Simple Words (Visitor Trying to Reach a House)

| Check | Real-Life Meaning |
|---|---|
| 1️⃣ Public IP | Does the house have a **public address** that visitors can look up? |
| 2️⃣ NACL | Will the **street-entrance guard** let the visitor in (and out again)? |
| 3️⃣ Route table | Is there a **road from the main gate to this street**? |
| 4️⃣ Security group | Will the **house-door guard** let this visitor through? |

> 📝 **About the order:** Lecture 120 listed these in a slightly different order (route table before NACL). The order doesn't matter much. **All four must be right** for the instance to be reachable. Check them one by one until you find the broken one.

> 🎯 **This is exactly what we lived through** in Lectures 119–122: the instance had a public IP and an open security group, but **no route to the Internet Gateway**. Check #3 was the culprit!

---

## ❓ Extra Important Question: "If two instances are in DIFFERENT subnets of the same VPC, does the NACL apply to their traffic?"

> 💡 **Answer:** **Yes.** The rule "NACLs don't apply within a subnet" is only for traffic between instances **in the same subnet**. When traffic crosses from one subnet to another, it **leaves** one subnet and **enters** the other, so it passes **both** subnets' NACLs: the **outbound** rules of the source subnet's NACL and the **inbound** rules of the destination subnet's NACL. And because NACLs are stateless, the **reply** has to pass the same two checkpoints in reverse. So if two instances in different subnets can't talk to each other, check the **NACL on both subnets** as well as the security groups (the route table's local route normally handles the routing).
>
> 🧒 **In simple words:** Visiting a neighbour on **your own street** skips the street guard. Visiting someone on **another street** means passing **your street's exit guard** and **their street's entrance guard**.

## 📋 Master Cheat Sheet

```
💂 SG  → resource level | allow rules only | STATEFUL  | any matching rule allows
🚧 NACL → subnet level   | allow + deny     | STATELESS | lowest-numbered matching rule wins
🚫 No rule matches → DENIED (both SG and NACL)
🏘️ Traffic inside one subnet → NACL NOT involved, only SGs
🌍 Traffic from outside → NACL first, then security group
🚧 NACL denies → request goes NO further

🕵️ "Can't reach my EC2 from the internet?" Check:
   1️⃣ Public IP / Elastic IP
   2️⃣ NACL (inbound + outbound, right port, your IP)
   3️⃣ Route table (route to Internet Gateway?)
   4️⃣ Security group (inbound from your IP?)
```

## ✅ Final Takeaways

```
💂 Security group = per resource, allow-only, stateful
🚧 NACL = per subnet, allow + deny, stateless, lowest rule number wins
🔀 From outside a subnet: NACL is checked first, then the security group
🏘️ Within one subnet: only security groups apply
🕵️ Unreachable instance? Check public IP, NACL, route table, and security group
```
