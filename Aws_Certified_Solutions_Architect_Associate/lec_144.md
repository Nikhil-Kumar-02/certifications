## 🧒 Quick Picture First

> 📝 Think of **"Version History" in Google Docs**. Every time the document changes, the old version is kept. You can look back at any earlier version, or **restore one** if you made a mistake. S3 versioning does the same for your files.

---

## 1️⃣ What Is Versioning? 📚

> 💡 **Core Idea:** Versioning keeps **multiple versions of the same object** in the same bucket: V1, V2, V3, V4...

### 🎯 Two Big Benefits

| Benefit | Detail |
|---|---|
| 🔍 **Track changes** | See how an object changed over time |
| 🛡️ **Protect against accidental deletion** | If you delete or overwrite something by mistake, an earlier version still exists |

> 🔗 **Recall Lecture 136:** This is the **versioning** technique we learned for improving **durability**.

### ⚙️ Key Facts

```
✅ Versioning is OPTIONAL
🪣 It's set at the BUCKET level (applies to all objects in the bucket)
```

---

## 2️⃣ Turning It On ⚙️

```
1️⃣ Open your bucket → Properties tab
2️⃣ Find "Versioning" (currently: disabled)
3️⃣ Edit → Enable → Save
```

> 💡 You can enable versioning **when creating the bucket** or **on an existing bucket later**.

### ⚠️ What About Objects That Were There Before?

> When you turn on versioning for a bucket that **wasn't versioned before**, all the **older objects get a version ID of "null"**. (The lecture says "none", but the console shows `null`.) They're not lost. They just have this special label for their first version.

---

## 3️⃣ Seeing Versions in Action 👀

### 🎓 The Demo

```
1️⃣ Versioning ON
2️⃣ Go to folder 2030 → Upload a NEW image named course0.png (same name as before)
3️⃣ Open the object → "Versions" tab
```

### ✅ Result

```
📄 course0.png
   ├── 🆕 Version 2 → uploaded just now
   └── 🕰️ Version 1 → uploaded about half an hour earlier
```

> 🎯 **Key Insight:** Uploading a file with the **same key** doesn't replace the old one. It **adds a new version**. Both are kept.

> 🧒 **In simple words:** Without versioning, saving over a file is like **writing over a page with a permanent marker**. With versioning, it's like **adding a new page on top of the old one** and keeping the old one underneath.

---

## 4️⃣ Can You Turn It Off? 🚫

### 🤔 The Experiment

> We tried to **turn versioning off** and **delete the old versions** to keep only the latest.

```
❌ You CANNOT turn versioning off once it's enabled.
✅ You can only SUSPEND it.
```

### 📌 Exam-Critical Rule

> **Once a bucket is versioned, it can never go back to being "non-versioned." Only enabled or suspended.**

---

## 5️⃣ What Does "Suspend" Do? ⏸️

| What | Effect of Suspending Versioning |
|---|---|
| 🆕 **New uploads** | **No longer create new versions** |
| 🗃️ **Existing versions** | **Remain as they are.** Nothing is deleted |

### 🎓 The Demo

```
1️⃣ Suspend versioning on the bucket
2️⃣ Check course0.png → still has 2 versions ✅ (old versions kept)
3️⃣ Upload a new copy of course1.png (in folder 10)
4️⃣ Check course1.png → only 1 version (no extra version was created)
```

> 🧒 **In simple words:** Suspending versioning is like **stopping the "Save as new version" feature**. Everything already saved stays safe. From that point on, new uploads just **overwrite** the current object instead of stacking up.

---

## ❓ Extra Important Question: "In a versioned bucket, what actually happens when I delete an object?"

> 💡 **Answer:** This is the heart of "protection against accidental deletion." When you **delete** an object in a versioned bucket (without naming a specific version), S3 **doesn't erase anything**. Instead it adds a special marker called a **delete marker** on top. The object **looks deleted** (it disappears from the normal list), but **all its earlier versions are still there**. To **bring it back**, you simply **remove the delete marker**, and the previous version becomes current again. To **permanently erase** something, you must delete **a specific version** on purpose.
>
> 🧒 **In simple words:** It's like **placing a "Removed" sticky note** over a file in a cabinet. The file is still in the drawer, and if you peel off the sticky note, it's back.
>
> 💰 **One cost tip:** Every version takes up storage space, and **you pay for all of them**. Over time, a busy versioned bucket can grow large. Later in the section, **lifecycle rules** will help you clean up or move old versions automatically.

## 📋 Master Summary Table

| Topic | Detail |
|---|---|
| 📚 **What it does** | Keeps multiple versions of an object |
| 🛡️ **Benefits** | Track changes + protect against accidental deletion |

| 🔧 **Optional?** | Yes |

## ✅ Final Takeaways

```
📚 Versioning = keep every version of an object (like Version History)
🛡️ Protects against accidental deletion and overwrites
⚙️ Set at the BUCKET level, optional, can be enabled any time
🕰️ Pre-existing objects get version ID "null" when you enable it
🚫 ONCE ENABLED, CAN NEVER BE TURNED OFF, only SUSPENDED
⏸️ Suspend = no new versions, but old versions stay
🔒 Object Lock requires versioning
💰 All versions cost storage, so watch the growth
```
