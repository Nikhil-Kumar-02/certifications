## 1️⃣ What Makes a Subnet "Public"? 🌍

> 💡 **Core Idea:** A **public subnet** is one where traffic is allowed to flow in **both directions**:

```
⬆️ From the subnet → to the internet
⬇️ From the internet → to the subnet
```

### 🔑 How Do You Enable This?

By adding an **Internet Gateway** to your VPC and pointing the subnet's traffic to it.

> 🧒 **In simple words:** An **Internet Gateway** is the **main gate of your colony**. Without it, the colony (VPC) is completely sealed off. With it, people and traffic can go in and out. 🏘️🚪

---

## 2️⃣ How Routing Works on the Internet 🛣️

> 💡 **Core Idea:** When you talk to a server on the internet, there is **no direct connection**. Your request hops through many **routers** along the way.

```
💻 You → 🔀 Router → 🔀 Router → 🔀 Router → 🖥️ Server
```

Each router has a set of **rules** that tell it which direction to send traffic, based on the **destination IP address**.

> 🧒 **In simple words:** Think of a **courier package**. It doesn't fly straight from you to the receiver. It goes through several sorting centres. Each centre reads the address and decides which truck to put it on next. Routers do the same job for internet traffic. 📦🚚

---

## 3️⃣ Route Tables in AWS 📋

> 💡 **Core Idea:** AWS routing works the same way. A **route table** is a list of rules that decides where network traffic from your subnet goes.

| Term | Meaning |
|---|---|
| 📋 **Route Table** | A collection of routing rules, linked to your VPC and subnets |
| 📏 **Route** | A single rule in the table |
| 🎯 **Destination** | "If the traffic is going to THIS range of IP addresses..." |
| 🚚 **Target** | "...then send it HERE." |

> 🧒 **In simple words:** A route table is a **signboard at a road junction**: "Going to the airport? Turn left. Going to the market? Turn right." Each line on the signboard is a **route**.

---

## 4️⃣ Reading a Route Table 👀

Here is an example route table with two routes:

| Route | Destination | Target |
|---|---|---|
| **Route 1** | `172.31.0.0/16` | `local` |
| **Route 2** | `0.0.0.0/0` | `Internet Gateway` |

### 🏠 Route 1: The Local Route

```
Destination: 172.31.0.0/16  (the VPC's own range, 172.31.0.0 to 172.31.255.255)
Target: local
```

> 🎯 **Meaning:** "If the traffic is going to any address **inside our VPC**, keep it **local** within the VPC."

> 🧒 **In simple words:** This is the rule for **internal colony traffic**. If you're visiting a neighbour inside the colony, you don't need to leave through the main gate. This route is what lets all instances in a VPC talk to each other.

### 🌍 Route 2: The Route to the Internet

```
Destination: 0.0.0.0/0  (every possible IP address)
Target: Internet Gateway
```

> 🎯 **Meaning:** "For **any other address** that isn't covered above, send the traffic to the **Internet Gateway**."

> 🧒 **In simple words:** This is the **catch-all** rule: "Anything not inside the colony? Take it out through the main gate." Remember from the CIDR lecture: `0.0.0.0/0` means **all IP addresses**.

---

## 5️⃣ The "Most Specific Route Wins" Rule 🏆

> 📌 **Exam Alert:** This is a classic exam concept!

### 🤔 The Puzzle

Both routes above can match the same address. For example, `172.31.0.10`:

```
✅ Matches Route 1: it IS inside 172.31.0.0/16
✅ Matches Route 2: it IS inside 0.0.0.0/0 (which covers everything)
```

So which route does AWS follow?

### 🏆 The Answer

> **The most specific route wins.** The "most specific" route is the one with the **smallest range of addresses**.

```
Route 1 (/16 = 65,536 addresses) ← smaller range = MORE specific ✅ WINS
Route 2 (/0  = all addresses)    ← bigger range  = LESS specific
```

### 📊 Two Worked Examples

| Destination IP | Routes That Match | Winner | Result |
|---|---|---|---|
| `172.31.0.10` | Route 1 and Route 2 | **Route 1** (more specific) | Stays **local** inside the VPC 🏠 |
| `69.209.0.10` | Only Route 2 | **Route 2** | Goes out to the **internet** 🌍 |

> 🧒 **In simple words:** Imagine you ask for directions to "House 5, Green Street, Colony A." One signboard says "All of Colony A → straight." Another says "Everything else → highway." The first one is **more specific** about your exact destination, so you follow it. Specific instructions beat general ones. 🧭

## ❓ Extra Important Question: "If I create an Internet Gateway and attach it to my VPC, is my subnet automatically public?"

> 💡 **Answer:** **No.** Creating the Internet Gateway is only the first step. For a subnet to become truly public, **all** of these must be in place:
>
> 1. ✅ An **Internet Gateway** is attached to the VPC (the main gate exists).
> 2. ✅ The subnet's **route table** has a route sending `0.0.0.0/0` to the Internet Gateway (the signboard points to the gate).
> 3. ✅ The instance has a **public IP address** (so the internet knows where to send replies).
> 4. ✅ The **security group** (and network ACL) allow the traffic.
>
> Miss any one, and the instance stays unreachable. This is exactly what we'll set up in the next demo.

|---|---|---|
| 🌍 **Public Subnet** | Subnet with two-way traffic to/from the internet | A street connected to the main road |
| 🚪 **Internet Gateway** | The VPC's door to the internet | The colony's main gate |

## ✅ Final Takeaways

```
🌍 Public subnet = traffic can flow BOTH ways between the subnet and the internet
🚪 Internet Gateway = what connects a VPC to the internet
📋 Route table = a list of routes; each route has a DESTINATION and a TARGET
🏠 Local route = lets everything inside the VPC talk to each other
🌐 0.0.0.0/0 → Internet Gateway = the route that sends outside traffic to the internet
🏆 If several routes match, the MOST SPECIFIC (smallest range) route wins
```
