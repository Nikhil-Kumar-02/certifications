## 2️⃣ What Is a Bucket? 🪣

> 💡 **Core Idea:** A **bucket** is the **fundamental container** in S3. **Everything you store in S3 must go inside a bucket.**

> 🧒 **In simple words:** If S3 is a giant warehouse, a **bucket is one big labelled storage room** that you rent. All your files (objects) live inside a room, and every room has its own name.

---

## 3️⃣ Create a Bucket 🛠️

Click **Create bucket**, then fill in the following:

### 📛 Bucket Name

| Rule | Detail |
|---|---|
| 🌍 **Globally unique** | Unique across **all AWS accounts in the world**, not just yours |
| 🔤 **Valid URL characters only** | **No spaces, no uppercase letters**. Lowercase letters, numbers, hyphens and periods are fine |
| 🌐 **Why so strict?** | The bucket name becomes **part of the URL** (for example, when we host a website from it later) |

> 🧒 **In simple words:** A bucket name is like a **website domain name**. Two people can't own the same one, and it can't contain spaces or capital letters. If your first choice is taken, add something unique, like your name or a number. In the demo, the instructor used `my-bucket-in28minutes`.

> 📝 *Bonus rule (not in the lecture): bucket names must be **3 to 63 characters** long.*

### 🌍 Region

> 💡 This is a **subtle but important point**:
>
> ```
> 🌐 S3 itself  = a GLOBAL service (you don't pick a region when you open the console)
> 🪣 A BUCKET   = lives in ONE specific region (you pick it when creating the bucket)
> ```
>
> The demo used **`us-east-1`** (the default).

### 🔒 Public Access

```
✅ Default: BLOCK ALL PUBLIC ACCESS
```

> 💡 We keep the default for now. There are several ways to grant public access, and we'll look at them later in the section.

### 🔐 Advanced Settings: Object Lock

> 💡 **Core Idea:** Some companies, because of **regulations or compliance**, must **never delete** certain objects. **Object Lock** prevents objects in a bucket from being deleted.

| Fact | Detail |
|---|---|
| 🔒 **Versioning required** | If you use Object Lock, **versioning is mandatory** |
| ⚙️ **In this demo** | We left Object Lock **disabled** (the default) |

> 🧒 **In simple words:** Object Lock is like a **sealed vault**: once something goes in, nobody can throw it out. We'll cover versioning and Object Lock in detail soon.

### ✅ Click **Create bucket**

You'll then see the bucket in the list with its **name, region, and creation time**. It should say it is **not open to the public**.

## 4️⃣ Tour of the Bucket's Features 🧭

Click into the bucket. S3 offers a **lot** of options. Here's a quick map (we'll explore each one step by step in later lectures):

| Area | What You Can Do |
|---|---|
| ⬆️ **Objects** | **Upload** files and folders |
| ⚙️ **Properties** | **Versioning**, **logging**, **static website hosting**, **encryption** |
| 🔐 **Permissions** | **Access Control List (ACL)**, **Bucket policy**, **CORS**, and more |
| 🧹 **Management** | **Lifecycle** rules, **Replication**, **Analytics and Metrics**, **Inventory** reports |
| 🚪 **Access Points** | Set up access for other services/applications to this bucket |

> 🎯 **Key Insight:** S3 is a **very flexible** service with many options. Don't worry about memorizing this list. We'll go through each item one at a time.

## 6️⃣ Choose a Storage Class 🗃️

> 💡 **Core Idea:** Different use cases have **different access needs**:
>
> - Do I need the file **immediately**, every time?
> - Can I **wait a few hours** to get it back?
>
> S3 offers different **storage classes** for different needs, and picking the right one **saves money**.

```
✅ For now: choose STANDARD storage class
```

> 📌 **Exam Alert:** Understanding storage classes is **very, very important**. A later lecture covers each one in depth.

---

## ❓ Extra Important Question: "Why is 'Block all public access' turned on by default, and when should I turn it off?"

> 💡 **Answer:** Because **accidentally exposing private data** is one of the most common (and costly) cloud mistakes. With the block on, even if someone sets a permissive rule by mistake, **nothing becomes public**. It's a **safety net**. You should turn it off **only when you intend to make content public**, such as hosting a **public website** from the bucket (which we'll do later). Even then, make only **what needs to be public** public. For private files like backups, logs and customer data, **keep the block on**.
>
> 🧒 **In simple words:** It's a **master lock on the storage room's front door**. You only unlock it deliberately, when you really want visitors walking in.
